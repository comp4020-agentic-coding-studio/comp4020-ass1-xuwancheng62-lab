Does the winner hold when the data changes?

One race is one array, and a lucky array can flatter an algorithm. This runs all four algorithms over 20 arrays of each starting shape, side by side. Read down a column for the ranking under that condition; read across a row for how one algorithm responds to the data it is given.

Press the button to measure all three. The big number is the average comparisons; underneath it is how many of that column's 20 arrays the algorithm used the fewest comparisons on. Within a column all four run on the identical 20 arrays; between columns the arrays differ, which is what a starting shape is. Counts comparisons only — not wall-clock speed or memory, and nothing here says anything about larger arrays. A run counts for every algorithm tied for fewest, so a column's wins can add up to more than 20.

Two of those columns say more about our code than about the algorithms. Bubble sort here is the basic fixed-loop version with no early exit, so it makes the same 120 comparisons in all three columns. Adding that early exit cuts its nearly-sorted average by nearly half — but it still lands third of the four there, ahead of only our own quick sort, so the flat 120 is our fault and the low ranking mostly isn't. Quick sort here always takes the last value as its pivot, which is why it does more work on nearly-ordered data than on random. Insertion and merge sort are the ordinary versions, so their columns are about the algorithms. Both choices can be repaired, and the section below races the repairs rather than asking you to take our word for it.

What we found — and does fixing it help?

Two of those four numbers are our fault, not the algorithm's. So we fixed all four and raced each fix against the original on the same array. Two of the four fixes average worse than the original on some starting shapes — not just on an unlucky array — which is the more interesting result: an improvement is only an improvement for particular data.

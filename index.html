Bubble, insertion, merge and quick sort all solve the same problem: put these bars in order, shortest to tallest. Pick one for each side, press Race, and watch how differently they get there — same bars, same starting array, wildly different amounts of work. Then change the starting data, and watch the winner change with it.

Which versions these are matters, because it changes the numbers below. Bubble sort here is the basic fixed-loop version with no early exit, so it makes the same 120 comparisons whatever the starting data — a bubble sort that stops early when a pass finds nothing to swap would be one of the fastest here on nearly-sorted input, not the slowest. Quick sort here always takes the last value as its pivot, which is why it does more work on nearly-ordered data; picking the pivot at random, or as the median of three, avoids that. Insertion and merge sort are the ordinary versions.
